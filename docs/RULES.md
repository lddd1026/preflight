# preflight 规则手册

> 每条规则讲清三件事：**怎么检测**（检测方式）、**报出什么**（检测结果）、**怎么修**（修复方案）。
> 每条还必须有一个**血案**（`incident`）—— 说不出出过什么事的，不是规则，是风格偏好。
>
> 上游：[KNOWLEDGE.md](KNOWLEDGE.md)（矩阵）｜ 格式与阶段：[PLAN.md](PLAN.md)

---

## 1. 规则的数据格式

```yaml
id: agent/no-request-timeout          # 唯一标识，domain/name
name: 模型调用没有超时
severity: high                        # blocker | high | medium | info
applies_to: agent                     # software | agent | both
context: both                         # consumer | enterprise | both
matrix:                               # 来自矩阵（通用规则可为空）
  mechanism: llm-call
  invariant: no-overrun
detect:                               # 检测方式（数据，不是代码）
  kind: ast
  target: llm_call_site
  require_kwarg: [timeout]
incident: |                           # 血案：出过什么事，有什么数字
  litellm 默认 600 秒/次。乘以 max_steps=20，最坏情况是 3 小时。
  provider 挂死（连上了不回包）时，命令行会一直僵在那里，用户只能 Ctrl+C。
  这不是性能问题，是有界性问题。
report: |                             # 报出什么（面向用户的文案）
  第 {line} 行的模型调用没有设置 timeout。
fix: |                                # 怎么修
  给调用加上 timeout=60（或走 fivewhys 的 FIVEWHYS_LLM_TIMEOUT_S 这类配置）。
refs: [FIV-19, 需求 NFR-3]
```

### 严重度定义

| 级别 | 含义 | 门禁 |
| --- | --- | --- |
| **blocker** | 会造成不可逆损害或安全事件 | **不能上线**，豁免需签字 |
| **high** | 会造成事故、明显白花钱、丢掉关键证据 | 需要签字豁免 |
| **medium** | 会吃亏，但不会立刻出事 | 记录，排期修 |
| **info** | 提示，供判断 | 不影响退出码 |

### 误报处理（v0.1 必须有）

| 方式 | 用法 |
| --- | --- |
| 行内忽略 | `# preflight: ignore agent/no-request-timeout` |
| 文件级忽略 | `# preflight: ignore-file` |
| 配置排除 | `[ignore] paths = [...]` / `rules = [...]` |
| **包装层声明** | `--llm-entry myapp/llm.py:call_model`（解决"参数传在 wrapper 里"的误报） |

## 2. 通用规则（`applies_to: both`）

### `general/hardcoded-secret` · blocker

| 项 | 内容 |
| --- | --- |
| **检测方式** | 文本扫描：`sk-` / `AKIA` / `ghp_` / 高熵字符串出现在源码、配置文件、CI 配置、文档中；以及 `os.environ.get("X", "sk-...")` 这类**带默认值**的读取 |
| **检测结果** | 文件:行 + 命中的模式类型（**不打印密钥内容本身**，只给前 4 位 + 长度） |
| **修复** | 移到环境变量；从 git 历史里清除（`filter-repo`）；**轮换密钥** |
| **血案** | 密钥提交进仓库后，即使删掉文件，git 历史里仍然在。唯一安全的处理是轮换 |

### `general/env-not-ignored` · blocker

| 项 | 内容 |
| --- | --- |
| **检测方式** | `.gitignore` 存在性 + 是否包含 `.env` / `*.env`（排除 `.env.example`） |
| **检测结果** | 缺 `.env` 规则，或 `.env` 已被 git 跟踪（`git ls-files`） |
| **修复** | 加进 `.gitignore`；若已跟踪则 `git rm --cached .env` 并轮换密钥 |
| **血案** | —（零容忍项，无争议） |

### `general/config-name-drift` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | **交叉比对字符串集合**：① 代码里读的环境变量名（`os.environ` / `os.getenv` / pydantic Settings 字段推导）　② `.env.example` / README / 部署文档里写的名字。差集即为漂移 |
| **检测结果** | 「模板里的 `FIVEWHYS_MODEL` 代码并不读；代码读的是 `FIVEWHYS_LLM_MODEL`」 |
| **修复** | 改名或加注释；把这份比对放进 CI |
| **血案** | 本项目作者在自己的项目上踩过：`.env.example` 写的是 `FIVEWHYS_MODEL`，而 pydantic 字段是 `llm_model` → 环境变量是 `FIVEWHYS_LLM_MODEL`。**多一个少一个词都不报错**（`extra="ignore"`），用户照着文档换模型 → 静默失效，而所有对外指标都标着一个没生效的模型名。更讽刺的是那个模板文件自己就写着「写成 `FIVWHYS_` 不会报错，只会静默失效」——**一个关于静默失效的警告，本身静默失效了** |
| **为什么重要** | 这是**纯代码检查发现不了、纯文档检查也发现不了**的一类问题 —— 它跨了两个文件。这正是 preflight 存在的理由 |

### `general/exception-swallowed` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：`except ...: pass` 或 `except: continue`，且 except 块内**既没有日志也没有把它转成输出** |
| **检测结果** | 「这里吞掉了异常，既没记也没返回」 |
| **修复** | 至少 `logger.exception(...)`，或把异常转成给上层的可读信息 |
| **注意** | **agent 里有合法的吞异常**（工具异常转成给模型的文字）。所以只有「吞了、既没记也没转成输出」才是问题。这条规则的误报风险主要来自这个区分 |
| **血案** | 静默失败让排查方向完全跑偏：日志里一切正常，但功能没生效 |

### `general/unbounded-loop` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：包含外部调用（网络 / LLM / DB）的 `while` / 递归，且没有迭代上限变量 |
| **检测结果** | 「这个循环没有上限」 |
| **修复** | 加上限 + 触发上限时记录原因 |
| **血案** | 死循环不只是卡住，是**持续花钱** |

### `general/no-rollback-plan` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | 存在性：`RUNBOOK*` / `ROLLBACK*` / `docs/` 下含 "rollback"/"回滚" 的文档 |
| **检测结果** | 「没有找到回滚方案」 |
| **修复** | 写一份，并**演练一次**（演练记录也要留） |
| **血案** | 没演练过的回滚方案等于不存在 |

### `general/no-runbook` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | 存在性：`RUNBOOK*` / `OPERATIONS*` / `ONCALL*` |
| **检测结果** | 「没有运维文档」 |
| **修复** | 至少写：怎么部署、怎么回滚、出什么事找谁、常见故障怎么处理 |

### `general/no-test-layer` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | 存在性 + 内容：有没有测试目录；CI 配置里跑了什么（单元？集成？） |
| **检测结果** | 「没有集成测试」或「CI 只跑单元测试」 |
| **修复** | 补上缺失的层。四个层次（单元 / 集成 / 契约 / 端到端）+ 六类非功能（性能 / 混沌 / 安全 / 兼容 / 可观测 / 验收）**各有盲区**，缺哪层就漏哪类 bug |
| **血案** | 每一层测试只能发现某一类 bug —— 只有单元测试的项目，并发和容量问题一律漏掉 |

### `general/tests-hit-network` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：测试文件里出现真实网络调用（`requests.` / `httpx.` / SDK 客户端实例化），且没有 mock/fixture 覆盖 |
| **检测结果** | 「测试会真的发请求」 |
| **修复** | 注入假客户端；把真实调用挪到标记为 `slow` 的冒烟测试 |
| **血案** | 会花钱、会不稳定、会在 CI 上随机红 —— 最后被人 `skip` 掉 |

### `general/no-eval-fingerprint` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | 存在性 + 内容：有没有评测/基准数据；有没有对它的哈希/快照文件 |
| **检测结果** | 「评测集没有指纹，改动无法被发现」 |
| **修复** | 生成快照（字节级指纹）+ CI 里校验 |
| **血案** | 改了评测集却不知道 → 「改进前 vs 改进后」的对比**整体作废** |

### `general/unpinned-dependency-upper-bound` · info

| 项 | 内容 |
| --- | --- |
| **检测方式** | 解析依赖声明：有没有上界（`<2` / `~=`） |
| **检测结果** | 「依赖没有上界，未来会静默升到不兼容版本」 |
| **修复** | 加主版本上界；或用 lock 文件 |

## 3. agent 专项规则（`applies_to: agent`）

> 全部来自矩阵的 `mechanism: llm-call` 那一行，加上 `no-budget-breaker` 之类。
> **这 12 条是 v0.1 的全部范围（S3）。**

### A 组 · 模型调用

#### `agent/no-request-timeout` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：找到 LLM 调用点（内置符号表 + `--llm-entry` 声明的包装层），检查 kwargs 里有没有 `timeout` |
| **检测结果** | 「第 N 行的模型调用没有设置 timeout」 |
| **修复** | `timeout=60`（或统一在 client 构造时设） |
| **血案** | litellm 默认 600 秒/次。× `max_steps=20` = **最坏 3 小时**。provider 挂死时命令行僵在那里 —— 这是**有界性**问题，不是性能问题 |

#### `agent/no-output-limit` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：LLM 调用点缺 `max_tokens` / `max_output_tokens` |
| **检测结果** | 「模型输出长度完全没有限制」 |
| **修复** | `max_tokens=2000` + 响应侧大小兜底 |
| **血案** | 实测一个 8MB 的回复让**单次调用**记账 **$0.84**，是单次硬上限的 8 倍 —— 而成本闸门是在调用**之后**才检查的，**拦不住**。这是我们唯一能主动设的成本上限 |

#### `agent/cost-from-price-table` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | 文本/AST：用了 `completion_cost()` / `cost_per_token` 查表，或手写 `tokens * 单价` |
| **检测结果** | 「成本从价格表推算，provider 换模型名时会静默归零」 |
| **修复** | 优先读 provider 上报的 cost（litellm 在 `_hidden_params["response_cost"]`），查表只作兜底 |
| **血案** | 请求 `deepseek/deepseek-chat`，DeepSeek 端返回的 model id 是 `deepseek-flash` → 查表失败抛异常 → 被 `except` 吞掉 → **成本恒为 0**。报表上「平均成本 $0.0000」看起来像不要钱。**这个 bug 离线测不出来**（假模型返回的 usage 同样算不出成本） |

#### `agent/model-name-scattered` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | 文本：模型名字面量（`"gpt-4o"` / `"deepseek/..."`）出现在 ≥2 个文件，或出现在非配置模块 |
| **检测结果** | 「模型名散落在 N 处」 |
| **修复** | 收口到一处配置 |
| **血案** | 换模型时漏改一处；而且「所有指标必须标注所用模型」这条约束会直接失效 |

### B 组 · 循环

#### `agent/tool-exception-uncaught` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：工具分发点（`tools[name](**args)` / `dispatch(...)` / registry 调用）周围没有 `try` |
| **检测结果** | 「工具执行没有异常兜底」 |
| **修复** | 把异常转成给模型的反馈文字，而不是让它冒泡 |
| **血案** | 模型编造工具名 → `KeyError` → **整次诊断崩掉**。而这本可以变成一句「没有这个工具，你能用的是 A/B/C」——**错误是给它的新信息，不是终点** |

#### `agent/unvalidated-model-output` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：`json.loads(response...)` 没有 `try`，或结构化输出没有 schema 校验（Pydantic / jsonschema） |
| **检测结果** | 「模型输出未校验就使用」 |
| **修复** | schema 校验 + 失败时把**具体错误**喂回去让它自己改 |
| **血案** | 模型返回非法 JSON 是**常态**，不是异常。未兜底 → 整次会话崩 |

#### `agent/unbounded-parallel-tools` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：工具调用被 `asyncio.gather` / `Promise.all` 并发，且没有并发上限 |
| **检测结果** | 「并行工具调用没有并发上限」 |
| **修复** | 加 semaphore 或分批 |
| **血案** | 一次并发几十个请求 → 直接被限流，整轮失败 |

#### `agent/plain-text-ends-session` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：`if not ...tool_calls: return/break` 的形态 |
| **检测结果** | 「模型只说话就被当成结束」 |
| **修复** | 改成推它一把（nudge），而不是结束 |
| **血案** | 模型经常先嘀咕一句「我先看看日志」，那只是思考不是结论。判死 = 这一次白跑，还要记进准确率分母 |
| **备注** | 误报风险中等（有些场景确实该结束）→ **建议默认报 info** |

### C 组 · 上下文

#### `agent/tool-output-unbounded` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：工具返回被直接写入 messages（`str(result)` / 未经过截断函数），且工具层没有长度限制 |
| **检测结果** | 「工具返回直接进上下文，没有长度限制」 |
| **修复** | 工具层渲染预算：截断 + **头部说明「共命中 M 条，显示前 K 条」** |
| **血案** | 一份 8MB 的返回会被**原样加进历史，之后每一次请求都再发一遍** —— 成本是**平方级**增长的 |

#### `agent/no-context-guard` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：主循环里没有「发送前估算 messages 长度」的检查 |
| **检测结果** | 「没有上下文闸门」 |
| **修复** | 发出去**之前**估算，超了提前停并说明原因；闸门按**该模型自己的窗口**算，不写死 |
| **血案** | 等 provider 回「context length exceeded」时，**那一次的钱已经花了**。而且写死闸门会在换模型时错一个数量级（实测窗口差 8 倍：131k / 128k / 1,048k） |

#### `agent/truncation-without-notice` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | 找到截断函数，检查返回值里有没有元信息（总数 / 已显示数） |
| **检测结果** | 「截断了但没有告诉模型被截断」 |
| **修复** | 头部加「共 N 条，显示前 K 条」 |
| **血案** | 模型不知道被砍过 → 以为看到的就是全部 → **推理直接错**。截断可以，但**不能悄悄截断** |
| **为什么这条有观点** | 现有项目都在比「我压了多少 token」，没有一个在检查「你压的时候告没告诉模型」 |

### D 组 · 护栏与结构化输出

#### `agent/no-budget-breaker` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST：主循环里没有累计成本 / 累计 token 的检查（步数上限不算，那是另一条） |
| **检测结果** | 「没有成本/token 熔断」 |
| **修复** | 累计用量紧贴调用记账 + 超过上限时停，并写一句可读的说明 |
| **血案** | 成本要查价格表（见 `cost-from-price-table`，查不到就恒为 0 → 上限形同虚设）；而 token 是 provider 直接报的，**成本算不出来时它是唯一还能用的刹车** |

#### `agent/output-field-has-default` · high

| 项 | 内容 |
| --- | --- |
| **检测方式** | AST + Pydantic：输出模型（`Diagnosis` 这类）的字段带默认值 → 该字段**不在 `required` 里** |
| **检测结果** | 「字段 X 有默认值，模型可以整段省略它」 |
| **修复** | 去掉默认值（用 `Field(...)` 强制必填） |
| **血案** | 作者踩过：`required` 当时只有 4 个字段，模型可以只交一句根因，**「结构化输出」名存实亡**。而且这个坑不会报错 —— 只是偶尔交上来少几个字段 |

#### `agent/no-evidence-check` · medium

| 项 | 内容 |
| --- | --- |
| **检测方式** | 输出模型里有引用/依据字段，但代码里没有对它的校验 |
| **检测结果** | 「结论里的依据没有核对」 |
| **修复** | 校验每条依据指向的调用**真的发生过**（不是格式对不对，是诚实性） |
| **血案** | 模型可以给你一份字段齐全、逻辑通顺、**依据全编造**的报告。而判分只看结论对不对 → **「答对但过程编造」比「我查不出来」更危险**：它让人相信一个没被验证过的推理 |

## 4. 文档层规则（由声明动态生成）

**这一层的规则不是预置的，是从项目自己的文档里长出来的。**

| 声明类型 | 生成什么检查 |
| --- | --- |
| `existence`「回滚执行 `scripts/rollback.ps1`」 | 该文件存在吗 |
| `quantity`「60 秒超时」「484 个测试」 | 数一下 / 查配置 |
| `constraint`「工具都是只读的」 | 找反例；找不到报 ⚠️「无法证明否定」 |
| `behavior`「每次诊断都落盘轨迹」 | 找可疑代码 + LLM 判断（必须带证据） |
| `plan`「M6 会做评测台」 | **不验证**，只记录 |

**另有三条固定的文档层规则：**

| ID | 级别 | 检测方式 |
| --- | --- | --- |
| `doc/no-readme` | high | README 不存在或为空 |
| `doc/claim-unfulfilled` | 按声明 | 声明未兑现（❌） |
| `doc/claim-unverifiable` | info | 无法验证（⚠️） |

### 报告的最终形态

```markdown
# RELEASE_REVIEW
日期：...   profile：agent-enterprise   模型：...（实际服务：...）

## 结论
🔴 NO-GO —— 2 个 blocker、5 个 high

## 自动检查
| 级别 | 规则 | 位置 |
...

## 文档兑现率  87% (33/38)
❌ 未兑现 5 条
  - README.md:14 「消息不丢」→ 没有找到对应的测试
⚠️ 无法验证 4 条
  - README.md:9 「5 分钟跑通」→ 性能声明，无法静态验证

## 待人工签核（3 条）
...

## 豁免记录
| 规则 | 谁 | 何时 | 为什么 | 到期 |
```

## 5. 规则统计
